01

The backend map

Before opening individual files, learn the path a typical fund-review request follows.

Think of the backend as a small workshop. The API is the counter where a request arrives. Data modules fetch and prepare the raw material. Analysis modules do the arithmetic. The agent layer coordinates the work. The route packages the finished result for the caller.

api/

The front counter

Matches URLs, checks or receives request data, calls the right function, and returns JSON or a stream.

agent/

The coordinator

Runs a defined sequence of specialist functions. The sequence is written in Python rather than invented by an AI.

analysis/ + data/

The workshop

Data code finds and cleans information; analysis code turns that information into metrics and summaries.

Concept · What is a backend?the other side of the request
What it is

The backend is the program running on a server. It receives requests from another program, performs work or retrieves data, and sends a response.

Why we use it

Fund calculations and data access need one trusted place to run. A browser should not have to contain all the calculation rules or hold private provider keys.

How this project uses it

The browser sends HTTP requests to the Python FastAPI service. The service finds a scheme, fetches public NAV data when required, calculates results, and responds with JSON or SSE.

Boundary to remember

The backend is not a database here. It does not create accounts or permanently save user portfolios. A request is work performed by a running service, not a stored user record.

Concept · API, HTTP, and JSONthe shared language
API

An agreed menu of addresses and actions. For example, GET /api/search means “search the official fund directory.”

HTTP

The request-and-response rules used to communicate across the network. A request includes an action (method), an address (path), headers, and sometimes a body.

JSON

A text format for named values and lists. It is like a labeled parcel: {"scheme_code":"123"} says what the value means, not just what the value is.

Why these fit together

The API defines the menu, HTTP carries a request to a menu item, and JSON commonly carries the structured input/output. File upload uses multipart instead because it can carry file bytes and ordinary fields together.

First important boundary:

“Agent” describes the coordination layer. It does not mean an LLM makes the standard health score or verdict. Those are calculated by ordinary Python rules.

02

App startup and FastAPI

The backend begins as a Python object, then a web server makes it reachable over HTTP.

Two programs working together

Uvicorn

The listener

Uvicorn listens for network requests and passes them to the Python web application.

FastAPI

The request handler

FastAPI matches a request to a route, validates declared inputs, runs the handler, and builds the HTTP response.

ASGI is the agreed interface between them. Imagine a plug and socket: Uvicorn and FastAPI can connect because both follow the same standard.

Concept · ASGI, from first principlesthe connection contract
What the letters mean

ASGI stands for Asynchronous Server Gateway Interface. It is a Python standard describing how an application server and a Python web app pass HTTP work to one another.

Picture it

Imagine two people using a courier service. The courier knows how to deliver a package; the receiving office knows how to process it. ASGI is the agreed delivery procedure between those two programs.

What is passed

The server gives the app request details (method, URL, headers, body) and a way to receive/send messages. The app returns response status, headers, and body data through that interface.

Why “asynchronous” matters

While one request waits for a network reply, an async app can work on another ready request instead of keeping the whole server idle. It does not make one CPU-heavy calculation magically faster.

How Truthfolio uses it

Uvicorn serves app.main:app. FastAPI is ASGI-compatible. Route functions use async def and await around network I/O and other asynchronous work.

What it is not

ASGI is not an API endpoint, a server product, or a library that calculates funds. It is the interface that lets the server and app cooperate. You rarely call it directly in route code.

Concept · Application factory and import timebuilding the app object
Factory

create_app() is a function that constructs and returns a configured FastAPI application. Factories keep setup in one place and make tests/deployments easier to configure.

Why the final assignment matters

app = create_app() runs when Python imports this module. Uvicorn’s app.main:app means “import app.main, then serve the object named app.”

Router

A router groups related routes, much like chapters group related pages. The prefix is added once, so the code can declare /search while the public path becomes /api/search.

Caution

Import-time work should stay small and predictable. Creating the application is not the same as processing a request; network warm-up is handled by the lifespan function.

What CORS actually does

A browser calls an address from a web page. If the page and API have different origins (protocol, host, or port), the browser asks whether the page is allowed to read the API response. Truthfolio’s CORS middleware configures the response that answers that browser rule.

It helps with

Allowing a known browser-based website—such as the local site at port 3000—to read responses from the API at port 8077.

It does not do

Authenticate a user, require an API key, or block command-line tools and other servers from calling the API.

Concept · CORS, why browsers askpermission for a web page to read
What is CORS?

Cross-Origin Resource Sharing: a browser-and-server mechanism for declaring which website origins may read a response from another origin.

What is an origin?

An origin is the combination of protocol, host, and port. http://localhost:3000 and http://localhost:8077 are different origins because the port differs.

Why CORS exists

Browsers protect a person’s logged-in sessions and data. A page from one site should not automatically be able to read private responses from another site just because both are open in the same browser.

What middleware does

Middleware is helper code wrapped around request/response handling. FastAPI’s CORS middleware adds response headers describing which origins, methods, and headers the browser may use.

The browser makes the decision

The server provides the permission information. The browser checks it and decides whether JavaScript on the calling page may read the response. CORS is not a network firewall.

What “preflight” means

For some cross-origin requests, the browser first sends an OPTIONS request asking “would this method and these headers be allowed?” If the reply permits it, the browser sends the real request.

Truthfolio’s current setting

Origins default to the two localhost port-3000 addresses. Methods and headers use *; credentials are enabled. Production should set the actual trusted website origins.

Why credentials are separate

Credentials are browser authentication material such as cookies. Allowing them only affects browser cross-origin behavior; it does not create accounts, sessions, or authentication logic in this backend.

What CORS cannot protect

A script, command-line client, mobile app, or another server can call the API without obeying browser CORS rules. Sensitive operations need real server-side authentication and authorization.

Configuration caution:

Allow only the website origins that should read this API in production. Broad methods/headers and credentials make a careful origin list especially important. CORS does not replace authentication, rate limits, or input validation.

Concept · Lifespan and startupwork around the app’s lifetime
What it is

A lifespan function runs startup work before requests are served and can run shutdown cleanup when the application stops.

Why use it

Shared resources can be prepared once per application run instead of repeatedly for every request.

Truthfolio use

It tries to load the AMFI scheme master early. This is a warm-up so the first search is less likely to wait for that initial download and parse.

Caution

The warm-up failure is intentionally ignored so the server can start. That also means “server started” does not prove AMFI is currently reachable; a real route may still fail later.

Cookie note:

The app enables credentials in CORS, which permits browsers to include credential information when otherwise configured to do so. This backend does not thereby gain accounts or a login system.

Startup: warm one reference book

The FastAPI lifespan function runs startup work before the app serves requests. Truthfolio asks AMFI for its scheme directory early so the first search is usually faster. If that early attempt fails, the app still starts and a later request can try loading it again. NAV histories are not all downloaded at startup.

backend/app/main.py · startup lifecycleOpen source file ↗
@asynccontextmanager
async def lifespan(app: FastAPI):

Requests, routes, and validation

A request has an address, an action, and sometimes data. The route is the backend function assigned to that combination.

Read and send actions

GET

Ask for information

Examples: GET /api/search?q=parag, or GET /api/health.

POST

Send information or start work

Examples: POST /api/review with a scheme code, or POST /api/portfolio with holdings.

Validation as a form checker

A request model is a Python description of allowed fields and values. Pydantic reads it and rejects invalid data before the route starts the main work.

Follow one real route

This small route accepts a fund code, looks up the official scheme, asks the review function to do the analysis, and shapes the final response.

backend/app/api/routes.py · review entry path (excerpt)Open source file ↗
async def _run_review(scheme_code: str, units=None, invested_amount=None):
    master = await amfi.get_master()
    scheme = master.get(scheme_code)
    if scheme is None:
        raise HTTPException(404, f"Scheme {scheme_code} not found in AMFI master.")
    try:
        state = await review_fund(
            scheme_code=scheme.code, scheme_name=scheme.name,
            category=scheme.category, base_name=scheme.base_name, amc=scheme.amc,
            units=units, invested_amount=invested_amount,
        )
    except ValueError as exc:
        raise HTTPException(422, str(exc))
    return ReviewResponse(**assemble_review(
        scheme_code=scheme.code, scheme_name=scheme.name,
        category=scheme.category, state=state,
    ))

The official name, category, and fund house are passed to the coordinator.

Concept · Request, route, response, and status codethe API transaction
Request

A message from a caller. It has an HTTP method, a path, headers, and possibly a query string or request body.

Route

A declared pairing between a method/path and a Python function. For example, @router.post("/review") maps POST requests to the review handler.

Response

The server’s answer: a status code, response headers, and a body. The body may be JSON or an event stream.

Status code

A compact signal about the request outcome: 200 success, 404 not found, 422 invalid input, 429 limit reached, 502 outside service failed, 503 feature unavailable, 500 unexpected server failure.

Why use status codes?

They let callers distinguish success from different kinds of failure without trying to guess from a sentence in the body.

Caution

A 200 response means the HTTP operation succeeded, not that an investment result is guaranteed or future performance is known. Status codes describe the software interaction, not financial certainty.

Concept · Reading the Python marks in the examplesthe small symbols have jobs
Import

from fastapi import APIRouter means “use the APIRouter tool defined in the FastAPI package.” Imports connect one file to another library or project module.

Decorator

@router.post("/review") is a decorator: a marker that tells FastAPI to register the function below it as the handler for POST requests to that route.

Type annotation

scheme_code: str documents that a value should be text. An annotation helps readers and tools; by itself it is not always runtime validation. Pydantic models provide the actual request checks used here.

Return value

return result hands a value back to the caller function or framework. FastAPI converts ordinary return values into an HTTP response according to the route setup.

Exception

raise HTTPException(404, ...) stops the normal path and signals an HTTP error response. try/except can catch a known error and map it to a deliberate response.

Why these patterns?

They separate declaration (route and input shape), normal work (function body), and failure behavior (exceptions), which makes API behavior easier to trace.

Concept · Input model and output modelform rules in code
Input model

A Pydantic BaseModel describes the fields a caller may submit and rules for each field. FastAPI uses it to parse and validate incoming data.

Output model

A response model describes the shape the route promises to return. FastAPI can validate and document that response contract too.

Why validate early?

Bad shapes and impossible ranges should be rejected before network requests and calculations begin. This reduces confusing downstream errors.

What validation cannot prove

A string can have the right type but refer to a nonexistent AMFI code. Data-dependent facts must be checked with the relevant directory or service.

Concept · Async, await, and concurrencywaiting without blocking everything
What “async” means

An asynchronous function can pause at an I/O wait (such as a network response) and let the event loop run another ready task.

What await means

“Pause this coroutine until this operation is ready; meanwhile, allow other coroutines to run.” It does not mean “start a new thread.”

Why use it here?

Fund and peer reviews wait on public HTTP services. Async I/O allows one service process to manage multiple waiting requests more efficiently than blocking at every network wait.

Concurrency vs parallel CPU work

Concurrency means several jobs can make progress over overlapping time. Parallelism means work runs at the same instant on multiple CPU cores. Async network I/O mainly provides concurrency.

Blocking work exception

CAS PDF parsing is ordinary blocking work, so its route uses asyncio.to_thread() to run it on a worker thread instead of blocking the event loop.

Caution

CPU-heavy Python work inside an async route can still hold up the event loop. Also, launching many tasks does not itself limit external traffic; Truthfolio separately uses a semaphore for NAV downloads.

Why a response builder?

Several paths can produce a fund review: a direct request, a streaming request, or a portfolio holding. A shared assembler helps them return a consistent review shape.

04

Finding the fund and loading NAV

AMFI answers “which official scheme is this?” mfapi.in answers “what has its published NAV history been?”

AMFI is the Association of Mutual Funds in India. It publishes the directory used here to resolve official scheme identities. NAV means Net Asset Value: the published per-unit value for a mutual-fund scheme. Truthfolio requests dated NAV observations from the separate mfapi.in service; it does not ask an LLM to make up missing prices.

AMFI

The official directory

Its feed lists scheme codes, scheme names, fund houses, categories, plan/option details, and ISIN identifiers.

mfapi.in

The historical values

Its per-scheme response contains NAV observations with dates. The backend turns them into ordered points.

Why store scheme identity as a record?

The Scheme dataclass groups the facts that belong together: official code, display name, base fund name, AMC, category, plan, option, and optional ISINs. A SchemeMaster keeps lookup indexes by code and ISIN, plus a search corpus for name matching.

Fuzzy search is tolerant of reordered or partial words, but the code also checks that distinctive words from the query actually appear. This reduces accidental matches on made-up names. Duplicate plan/option versions collapse into one fund result, preferring Direct-Growth where available.

Search is not the same as trusting user text

Make outside calls asynchronous and bounded

The client uses httpx.AsyncClient to perform an asynchronous HTTP request and Tenacity to retry failures up to three attempts. A shared semaphore allows at most 16 NAV downloads at once in this running backend copy.

Why cap simultaneous downloads?

A portfolio can trigger many holding reviews, and each review can compare peer funds. The semaphore is a traffic light that prevents an uncontrolled burst of requests to the NAV service.

Concept · Dataclasses and “clean” data objectsgive values a useful shape
What a dataclass is

A Python helper for making a class whose main job is to hold related fields, such as a scheme code and name or one date and NAV value.

Why use one?

Instead of passing anonymous tuples like ("123", 100.5), later code can say point.nav and point.on. Named fields are easier to read and harder to mix up.

Truthfolio examples

Scheme, NavPoint, and NavSeries give AMFI and NAV data a predictable internal shape after parsing.

What it does not do

A dataclass does not automatically validate external data. Parsing code still has to convert values and discard malformed rows before creating reliable objects.

Concept · Fuzzy search and official identifiershelpful matching without guessing identity
Fuzzy search

A matching method that can tolerate partial or reordered words. It helps when a person types a shortened or imperfect fund name.

Why use it?

Official scheme names can be long and contain plan/option wording. Exact whole-string matching would make search unnecessarily brittle.

How this code narrows results

RapidFuzz proposes candidates; the code also checks distinctive query tokens, groups plan variants, and prefers a Direct-Growth scheme where available.

Caution

A fuzzy score is not proof of identity. The backend returns the official AMFI code and checks that code on later review requests instead of trusting the display name as an identifier.

backend/app/data/amfi.py · search precision gateOpen source file ↗
def passes_gate(text: str) -> bool:
    if not meaningful:
        return True
    present = sum(1 for token in meaningful if token in text)
    return present / len(meaningful) >= 0.6

matches = process.extract(
    query, corpus, scorer=fuzz.token_set_ratio,
    limit=limit * 6, score_cutoff=45,
)

The fuzzy matcher first proposes candidates (score at least 45, with up to six times the requested result count). The precision gate then requires at least 60% of the user’s meaningful words to appear in the candidate text. Finally, the code collapses plan/option duplicates and gives Direct and Growth variants preference points. These are search-ranking rules, not claims that one variant is right for every investor.

Concept · Retry, timeout, and semaphorenetwork calls need guardrails
Timeout

The maximum time to wait for one outside request. A timeout prevents a request from waiting forever for a server that is not responding.

Retry

Try a failed operation again. Truthfolio’s NAV fetch is configured for up to three attempts with increasing waits between attempts.

Semaphore

A shared counter limiting how many NAV fetch tasks may enter the network section at once; here the limit is 16.

Why combine them?

Timeouts bound one wait, retries tolerate temporary failures, and the semaphore controls bursts. They solve different problems, so one is not a substitute for another.

Trade-off

Retries can increase latency and repeat load if a service is unhealthy. The attempt count is capped; callers should still be prepared for the final request to fail.

Scope limit

The semaphore is in this Python process, not a company-wide traffic controller. Several replicas can each have up to their own limit.

Cache and outside services

A cache is a temporary saved copy, so the backend can reuse fresh public data rather than download it again.

Three possible places the fund directory can come from

1 · MemoryFastest; current running copy
2 · JSON cacheSaved on the local filesystem
3 · AMFIDownload and parse if no fresh copy
4 · IndexBuild code, ISIN, search indexes
5 · ReuseMemory copy until restart

For NAV history, the module checks the JSON cache. A fresh entry is parsed; a missing or old entry triggers a request to mfapi.in. The cache TTL defaults to 12 hours for NAV. The AMFI directory defaults to 24 hours on disk.

backend/app/data/cache.py · TTL decisionOpen source file ↗
def read(key: str, ttl_seconds: float) -> Any | None:
    path = _path_for(key)
    if not path.exists():
        return None
    try:
        payload = json.loads(path.read_text())
    except (json.JSONDecodeError, OSError):
        return None
    if time.time() - payload.get("_ts", 0) > ttl_seconds:
        return None
    return payload.get("data")

What “best effort” means:

Writing a cache copy is not allowed to break the actual request. If saving fails due to a file-system problem, the current request can still return the fetched data. Reading invalid JSON text is treated as a miss; a valid JSON value with an unexpected shape is not fully guarded and may raise an error.

Concept · Cache key, TTL, cache hit, cache missrules for reusing a copy
Cache key

A label that says which saved result is being requested. For NAV, the key is built from the scheme code, so different schemes do not share the same saved history.

TTL

“Time to live”: the maximum age for which a saved entry may be reused. Different features can choose different TTLs depending on how quickly their data changes.

Cache hit

A valid, not-too-old entry exists. The module can reuse it rather than making the network call again.

Cache miss

The file is absent, unreadable, contains invalid JSON text, or is past its TTL. The data module treats those cases as unavailable and may fetch a replacement.

Why cache?

It can reduce response time and repeated calls to public/paid services. For Tavily, a hit can also avoid spending another search credit.

What caching cannot guarantee

A fresh-by-clock copy may still be stale relative to a newly published value. TTL is a reuse policy, not a promise that the content is the latest possible data.

Concept · Why a local JSON file cache?simple and intentionally limited
Why JSON?

Many data objects already consist of strings, numbers, lists, and dictionaries. JSON is a straightforward text format to save and read without adding a database dependency.

Why local disk?

This project can reuse data within one backend instance with little setup. It is simple for development and a single long-running service.

Trade-offs

Local files are not automatically shared between replicas, do not provide database transactions or query capabilities, and can disappear if the deployment uses temporary storage.

Privacy and correctness caution

The cache is not encrypted user storage. Do not treat it as a place to store sensitive account data. Cache keys and TTLs must match the data being cached so one result cannot be reused for the wrong request.

Concept · Lock and “load once” behavioravoid duplicate first-time work
What a lock does

An async lock lets one coroutine at a time enter a protected section. Other coroutines wait until the lock is released.

Why AMFI uses one

If several first requests arrive together with no master loaded, one request loads and parses it; the others wait and reuse the prepared copy instead of doing the same work simultaneously.

Analogy

One person checks out the reference book from the desk; the next person waits a moment instead of ordering another copy at the same time.

Scope

This lock only coordinates tasks inside the current Python process. It does not synchronize separate server replicas or separate machines.

Why break one review into specialists?

What a “state” is

AgentState is a typed dictionary shared across steps. Think of it as a clipboard: the quant specialist writes metrics, the peer specialist adds ranks, and later specialists read those fields and add their own results.

Analysis values

metrics, qualitative, peers, evidence, score, verdict, and narrative.

Control and progress

task, remaining plan, next-node name, progress steps, and whether optional AI was used.

Concept · Graph, node, edge, supervisorthe vocabulary behind LangGraph
Graph

A set of steps and rules for moving between them. A flowchart is a useful picture of a graph.

Node

One unit of work in the graph. In this project, a node is a Python function such as gather_quant or synthesise.

Edge

A connection that says where control goes after a node. Each specialist reports back to the supervisor; the supervisor selects the next planned specialist.

Supervisor

The coordinator that reads the task plan and dispatches the next node. Here it follows a list of names rather than asking a model to choose actions.

State

The shared clipboard: values written by earlier nodes and read by later nodes. LangGraph combines node updates into the state passed along the graph.

Why use a graph library?

It makes the flow explicit, reusable, and streamable. A specialist can remain focused on its work rather than manually calling every next function.

Why state values are plain data

The graph stores dictionaries, lists, numbers, and strings so state can be streamed and inspected. Large library objects are not needed as shared state.

Caution

A graph only guarantees the structure programmed into it. It does not prove that source data is correct or that a scoring rule is financially appropriate.

Concept · TypedDict is not a Pydantic modeltype hints versus runtime checks
TypedDict

A Python typing helper that documents which named keys a dictionary is expected to contain and what kinds of values they hold.

What it does here

AgentState helps developers and editors understand the fields shared between graph steps.

Important difference

TypedDict does not turn the dictionary into a runtime-validated object. Pydantic request models perform input validation at the API boundary; graph state is ordinary dictionary data.

Why both?

Request models protect the public API shape. A typed graph state documents the internal workflow shape without repeatedly converting it to a different object type.

One subtle but important boundary

Deep review can add researched web claims to the evidence list. The current synthesise() function receives metrics and peer data, not the combined evidence list. Therefore those web claims can enrich the evidence/explanation output, but do not alter the numeric score, confidence, or standard verdict.

Concept · Why compile and reuse the graph?build the route map once
What compile means here

LangGraph is given the node functions and edges, then produces a runnable graph object.

Why cache that object?

@lru_cache remembers the built supervisor in process memory. Later tasks reuse the same graph structure instead of rebuilding it each time.

What is reused

The graph definition and wiring are reused; each review still receives a new initial state and performs its own analysis.

Caution

Reusing the graph does not make user results persistent. Process memory is local to one running copy and is lost when that copy restarts.

Metrics, evidence, and verdict

Published NAV points become returns and risk measurements; the rules turn available measurements into a score and a named outcome.

First clean and order the timeline

analysis/metrics.py creates a dated Pandas series, removes duplicate dates (keeping the last), and sorts in chronological order. NumPy and Pandas help organize and calculate values; they do not decide the product’s scoring policy.

daily return = today’s NAV ÷ previous NAV − 1
example: 105 ÷ 100 − 1 = 0.05 = 5%

Growth and consistency

Trailing 1-, 3-, and 5-year returns; since-inception CAGR; rolling 3- and 5-year outcomes over multiple start dates.

Risk and downside

Annualized volatility, Sharpe ratio, Sortino ratio, and maximum drawdown from a previous peak.

backend/app/analysis/metrics.py · the core formulasOpen source file ↗
def _cagr(start_nav, end_nav, years):
    if start_nav <= 0 or years <= 0:
        return None
    return (end_nav / start_nav) ** (1.0 / years) - 1.0

def _annualised_vol(rets):
    if rets.size < 2:
        return None
    return np.std(rets, ddof=1) * np.sqrt(252)

def _max_drawdown(s):
    if s.empty:
        return None
    running_max = s.cummax()
    drawdown = s / running_max - 1.0
    return float(drawdown.min())
CAGRDivides end NAV by start NAV, spreads that growth across the number of years using a root, then subtracts 1 to express the annual rate.
Annualized volatilityMeasures how spread out daily returns are, then scales the daily measure to a year using √252, the configured trading-day convention.
Maximum drawdownAt every point, compare the NAV to the highest NAV seen so far. Keep the most negative difference; a result of −0.42 means a worst observed fall of 42% from a previous peak.
Concept · CAGR, volatility, and drawdownthree different questions about history
CAGR

Compound Annual Growth Rate answers: “What steady yearly rate would connect the start value to the end value?” It smooths the path; it does not claim each year actually earned that rate.

Why annualize?

A 3-year result and a 5-year result cover different lengths. CAGR expresses multi-year growth as a comparable per-year rate.

Volatility

A measure of how widely daily returns move around. Higher volatility means a bumpier historical path, not necessarily a forecast of future movement.

Drawdown

The percentage fall from a previous highest NAV to a later lower NAV. Maximum drawdown keeps the worst observed peak-to-trough fall.

Sharpe and Sortino

Both compare return with risk. Sharpe uses overall volatility; Sortino focuses on negative daily returns. Neither is a guarantee or a single complete measure of risk.

Data caution

These calculations are only as useful as the NAV dates and observations. Short histories may not support longer windows; the code returns missing values or omits rolling windows when observations are insufficient.

CAGR = (ending NAV ÷ starting NAV)1 ÷ years − 1
Example: ₹10,000 → ₹15,000 over 3 years gives about 14.47% per year
Annualized mean return = average daily return × 252
Sharpe = (annualized return − configured risk-free rate) ÷ annualized volatility
Sortino uses downside deviation instead of total volatility

The current default annual risk-free comparison rate is 6.5% (HPR_RISK_FREE_RATE can change it). In this formula, it is a configurable baseline subtracted from the measured annual return; it is not a promise that an investor can actually earn that rate without risk.

For a rolling 3-year result, the backend starts at monthly observations, looks forward three years for each possible start, and records the annualized return. It then reports the minimum, median, maximum, number of windows, and fraction of windows below zero. This answers “how did many possible start dates turn out?” rather than showing only one chosen start date.

Returns need a comparison group

A return can be high or low depending on the wider market. Peer comparison selects same-category Direct-Growth schemes, excludes the subject from the candidate set, limits each AMC to two schemes, and analyzes at most 18 peers. The reported comparison includes the subject fund among the ranked values.

A percentile is an approximate position in that comparison set. For example, 0.80 means the value is at least as good as about 80% of the compared values, while respecting whether high or low is better for that metric.

Concept · Percentile and peer comparisonrelative performance, not absolute quality
What a percentile says

It locates a value within a selected comparison group. An 80th percentile suggests the fund’s value is at least as good as about 80% of the compared values for that metric.

Why compare peers?

Two funds can have the same return but belong to categories with different conditions. A peer group adds context about similar schemes.

Direction matters

Higher return and ratios are generally better; lower volatility is better; drawdown closer to zero is better. The code checks each metric’s intended direction.

Sample caution

This is a selected bounded sample, not every fund in the category. Missing peer histories are dropped, and sample composition can affect the rank.

Percentile is not a probability

An 80th percentile is not an 80% chance of beating peers in the future. It describes the relative position in this historical comparison.

Recommendation caution

The separate alternatives endpoint applies transparent filters, but those results are research leads—not personalized recommendations to buy or switch.

How the composite score is built

Each available component receives a 0–100 sub-score. Each component also has a fixed importance share. If a component is unavailable due to insufficient history, the remaining used weights are effectively normalized by dividing by their sum.

ComponentWeightWhat it reflects
Long-term return0.225-year CAGR, or 3-year when 5-year is unavailable; 0–20% maps to 0–100, capped.

A small worked example

Suppose all five components are available and their sub-scores are: long-term return 70, risk-adjusted 60, peer standing 80, consistency 90, and drawdown 50.

70 × 0.22 + 60 × 0.26 + 80 × 0.30 + 90 × 0.14 + 50 × 0.08
= 15.4 + 15.6 + 24 + 12.6 + 4

If the peer-standing component is available at 80/100 (peer percentile 0.80), the rule “health at least 62 and peer percentile at least 0.45” selects Continue. This example explains the arithmetic; it does not imply that these are real results for any specific fund.

When some component is missing, the code excludes its weight and divides by the sum of weights that remain. For example, if drawdown is unavailable, it does not automatically count as zero; the available weighted total is divided by 0.92 instead of 1.00.

Drawdown sub-score maps a 20% fall to 100 and a 60% fall to 0, clamping values outside that range. Consistency prefers the 5-year rolling window; it subtracts four points for each percentage point of negative windows, so 25% negative windows maps to 0. Confidence is based on both data completeness (the sum of present component weights) and whether component scores generally agree; it is clamped between 0.25 and 0.95. Confidence is a property of available evidence, not a promise that the verdict is correct.

Concept · Score, verdict, confidence, evidencerelated fields with different meanings
Health score

A 0–100 combination of weighted component scores. It summarizes the product’s selected historical measures.

Verdict

A label selected by ordered threshold rules. The score and peer percentile are inputs to those rules.

Confidence

A code-defined indicator combining data completeness and agreement among available components. It is not a statistical confidence interval and not a guarantee.

Evidence item

A human-readable statement with a direction (positive, negative, neutral), weight, confidence, and source. It makes the reasoning easier to inspect.

Why keep them separate?

A score is a numeric summary, a verdict is a rule-based category, confidence indicates limitations/consistency, and evidence tells a reader what facts contributed.

Interpretation caution

Do not read the confidence field as the chance that an investment will succeed. It describes how the product’s input evidence looks under its own formula.

Evidence explains; rules decide

build_evidence() turns metric and peer facts into readable items. An item can include a claim, category, direction, importance weight, confidence, and source references. The ledger helps people inspect the reasons. The arithmetic score is produced by the explicit scoring functions.

Not regulated advice:

Thresholds and portfolio rules are product rules of thumb. They are not regulated ratings, promises, or personalized investment instructions.

SSE, explained in code

Server-Sent Events keep one HTTP response open so the server can send progress updates before the final result.

Normal response or progress stream?

Ordinary route

Wait, then get one answer

POST /api/review waits for the review and returns one JSON object.

SSE route

Get updates, then the answer

GET /api/review/stream sends named progress events, then a final result event.

event: step
data: {"message":"Compared against same-category peers"}

event: result
data: { ...final review... }

An event consists of an event name and a data line. A blank line ends the event. The stream flows from the server to the caller; the caller does not send new instructions through that same stream.

Concept · SSE protocolmany messages in one HTTP response
What SSE is

Server-Sent Events is a text-based format for sending named messages from a server to a client over a long-lived HTTP response.

Why choose it?

Long reviews can take time. Progress messages keep the caller informed without repeatedly polling “is it done yet?”

One-way direction

The server can send multiple events, but the client cannot send a new command back on that same stream. A new instruction needs another request.

Event framing

Text fields such as event: and data: are separated by a blank line. Truthfolio places JSON text in the data field.

Why the blank line matters

It marks the end of one event. Without a complete frame, a receiver may keep waiting for more bytes before delivering the message to application code.

Why native browser EventSource is not the whole story

The browser’s built-in EventSource interface opens GET streams. Truthfolio’s portfolio stream is POST because it accepts a JSON body, so a client needs a fetch-based stream reader or equivalent rather than assuming EventSource can send that body.

Connection cost

The HTTP connection stays open while work continues. Long or numerous streams use server, proxy, and network resources; deployment timeouts and buffering behavior matter.

Disconnect and errors

A network can close mid-stream. Once response headers have been sent, the server generally cannot replace the HTTP status; a stream event can report errors only if the connection is still usable.

Frame builder: two lines plus a blank line

def _sse(event: str, data: dict) -> str:
    return f"event: {event}\ndata: {json.dumps(data, default=str)}\n\n"

Data lineThe Python dictionary is converted to JSON text for the stream.
Blank lineThe final \n\n tells the receiver this event is complete.

Portfolio analysis

Each submitted holding receives the same fund-review treatment, then a separate calculation combines successful holdings.

What a holding needs

scheme_code + units held + average purchase NAV

PortfolioRequest allows between 1 and 40 holdings. A holding with a missing scheme, failed review, or missing latest NAV is not included in the successful aggregate.

One holding’s path

1
Find scheme identity.

Resolve the supplied official scheme code against the AMFI directory.

2
Calculate amount invested.

Multiply units by the average purchase NAV supplied by the caller.

3
Run the same fund-review graph.

Gather NAV metrics, compare peers, build evidence, score, and explain.

4
Add personal position figures.

Use the latest NAV from the computed report to calculate current value and gain.

Personal position equations

invested = units × average purchase NAV
current value = units × latest NAV
gain = current value − invested
return fraction = gain ÷ invested

The returned personal return is a fraction: 0.10 means 10%. It is total return from the supplied cost basis, not annualized. The request does not contain purchase dates or cash flows, so the backend cannot derive a time-weighted personal return.

Concurrency: many analyses, bounded downloads

backend/app/api/routes.py · parallel holding analyses (excerpt)Open source file ↗
inputs = [HoldingInput(h.scheme_code, h.units, h.avg_nav) for h in req.holdings]

    raise HTTPException(422, "None of the submitted funds could be analysed.")

asyncio.gather() starts the holding analyses without waiting for each one to finish before starting the next. Separately, the NAV semaphore limits how many network downloads happen simultaneously. So the backend can work on many holdings while still controlling the outside request rate.

Aggregate the successful holdings

  • Sum invested value, current value, gain/loss, and total return.
  • Calculate each holding’s share of current portfolio value.
  • Group current value by fund category.
  • Measure concentration using HHI: square each holding’s share and add the squares.
  • Calculate current-value-weighted portfolio health, then apply a concentration penalty.
  • Return a portfolio verdict, best/worst personal return, and action observations.
HHI = share₁² + share₂² + … + shareₙ²
Two equal holdings: 0.5² + 0.5² = 0.50
One holding: 1.0² = 1.00

Concept · Partial failure in a portfolioone holding can fail without losing all results
Why allow partial success?

A portfolio may contain several funds. One unavailable scheme should not necessarily prevent the caller receiving useful results for the other holdings.

Current behavior

Each holding analysis may return a result or None. The route aggregates the successful items and reports how many failed.

All holdings fail

The ordinary portfolio endpoint raises HTTP 422 when none can be analyzed. The stream sends an error event rather than a final result.

Important visibility limit

The portfolio result gives a failure count, not a detailed per-holding diagnostic reason for every failure. That makes it less useful for debugging than a richer error report would be.

Concept · HHI and concentration penaltya simple concentration signal
What HHI measures here

Take each fund’s fraction of current portfolio value, square each fraction, then add the squares. Larger values indicate more concentration in fewer holdings.

Why square the shares?

Squaring makes large shares count disproportionately more. One 100% holding gives 1.0; two equal 50% holdings give 0.50.

What it does not measure

It does not inspect the underlying stocks inside each mutual fund. Two different funds may own many of the same companies, but this backend does not calculate that overlap.

Penalty caution

The concentration deduction and portfolio verdict use fixed product thresholds. They are a transparent product heuristic, not regulated suitability advice.

CAS statement import

A Consolidated Account Statement is uploaded, parsed for active holdings, and matched to the official scheme directory.

CAMS and KFintech maintain mutual-fund account records. The route accepts a PDF and optional password. The casparser library reads it. Because PDF parsing is blocking work, the backend sends it to a worker thread so the main asynchronous request loop can continue serving other requests.

Read a limited number of bytes

Freshness policy

By default, statements older than 30 days get a warning. Statements older than 90 days are rejected.

Sensitive content

The route does not intentionally write or log the PDF/password or send them to search or AI. It clears its local references after parsing; this is not a guaranteed secure erase of Python memory.

Concept · Multipart file uploadfile bytes plus ordinary form fields
Why not JSON?

JSON is good for text, numbers, lists, and objects. A PDF is arbitrary binary file data, so browsers commonly send it in a multipart form that can include both a file and a password field.

What UploadFile provides

FastAPI gives the route an upload object with a way to read file bytes and close the upload. The route reads only the configured maximum plus one byte.

Why a worker thread?

The PDF parser is synchronous/blocking. Moving it with asyncio.to_thread() lets the event loop attend to other asynchronous requests while parsing runs.

Privacy boundary

In-memory handling avoids intentionally writing the PDF or password to disk, but it is not cryptographic erasure. Temporary memory, crash dumps, platform internals, and logs require their own operational controls.

Matching strategy

When a statement row has an official scheme code, use it. If that is missing, the importer can use an ISIN to look up the official scheme.

Input is still untrusted

A file extension does not prove that a file is a valid or safe PDF. Size checks and parser error handling limit some risks, but upload services should also use current libraries and deployment-level limits.

Concept · What is an LLM and what is a provider?text generation is not arithmetic truth
LLM

A Large Language Model is software trained to produce text based on input text and learned patterns. It is useful for wording, summarizing, and answering within a supplied context.

Provider

A provider is the external service company that runs a model and exposes it over a network API. Truthfolio can select Anthropic or Groq through its provider configuration.

Why not let it decide the score?

Text generation can be plausible without being numerically correct. Truthfolio computes the standard metrics and verdict in code, then may ask the model to explain those results.

Provider call path

A specialist builds context, the provider client sends a network request with a secret API key, the service returns generated text, and Truthfolio parses/uses that response.

What leaves this service?

When an optional AI/search feature is used, the data needed for its prompt or query leaves the backend and is sent to the selected provider. Review the provider’s data policies before enabling it.

Reliability caution

A model can misunderstand, omit context, or make unsupported claims. Code validation and source grounding reduce some failure modes, but generated text should not be treated as verified fact by itself.

Concept · Prompt, context, and output validationinstructions are not a guarantee
Prompt

The instructions and information sent to the model. A system prompt describes the task and boundaries; user/context content supplies the facts to explain.

Context

The specific metrics, evidence, holdings, or source snippets provided for one request. More context is not always better: it can cost more, exceed limits, or introduce irrelevant material.

Output validation

For structured features, the backend checks returned fields, types, and citations before returning the result. This catches malformed output, not every false statement.

Why keep fixed caveats in code?

Important educational warnings should not depend on the model remembering to include them. The narrative node adds the canonical caveats after generation.

Prompt-injection caution

Text retrieved from the web can contain instructions aimed at the model. Treat retrieved pages as untrusted data, separate them from system instructions, validate output, and never grant the model unrestricted tools.

Fallback meaning

When optional narrative generation is disabled or fails, the backend can use a code-written template. This preserves a result without pretending the model succeeded.

Concept · Citation and source appraisaltraceability helps; it is not a fact-check oracle
Citation

A reference connecting a claim to a source, usually with a stable number, title, and URL. Deduplication avoids listing the same URL repeatedly.

Appraisal score

A rule-based 0–1 score using domain, publication date, and corroboration. It controls which sources can be used for extraction.

Why appraise?

Search engines return pages of mixed quality and age. Filtering can reduce reliance on weak or stale material before asking a model to summarize it.

Important limitation

A score such as 0.80 is not an 80% probability that a page is true. The rules cannot independently verify every article’s content or detect every coordinated/incorrect source.

Research boundary

The standard review does not automatically use Tavily. The explicit research route is the credit-spending path, and the normal numeric verdict currently does not consume the combined web evidence.

Budget and cache

Search results are cached and successful uncached searches count toward a per-process daily cap. A cache hit can avoid another external request.

Operations and system boundaries

How configuration, errors, limits, and process-local memory shape what operators should expect.

Where settings come from

Settings uses Pydantic Settings to read environment variables and a local .env file. Most settings use the HPR_ prefix. Provider selection and keys accept both common unprefixed names and prefixed alternatives.

Concept · Configuration, environment variables, and secretschange behavior without editing code
Configuration value

A value that changes how the service behaves, such as a timeout, cache path, provider, or allowed browser origin.

Environment variable

A name/value supplied to a running program by its shell or deployment platform. For example, HPR_NAV_TTL_HOURS=12.

Why not hard-code everything?

Development, staging, and production may need different URLs and limits. Environment settings let the same application code run in each environment.

API key

A secret credential that lets the backend use an outside service. A provider key is not a user login, and should not be put in browser code or committed to source control.

Settings cache

@lru_cache makes get_settings() return the same Settings object after its first call. This avoids rereading settings and recreating the cache directory repeatedly.

Caution

Changing an environment variable after settings have been loaded may not affect the current process. Restart it, and rotate exposed credentials rather than merely deleting them from a local file.

What belongs to one running copy?

Memory

Loaded AMFI master, compiled graph, and usage counters remain in a process’s memory.

Local disk

JSON cache files live in that instance’s configured cache folder.

Not shared automatically

Multiple app instances have separate in-memory counters and may have separate filesystems.

Concept · Authentication, authorization, and CORS are differentdo not confuse browser permission with identity
Authentication

Answers “who is making this request?”—for example, by checking a session or token.

Authorization

Answers “is this identified caller allowed to perform this action or see this data?”

CORS

Answers a browser-specific question: “may JavaScript from this website read this response?” It does not identify or authorize the caller.

Truthfolio’s current boundary

The backend currently has no account/login system or per-user saved portfolio. CORS is not a substitute for those controls if private, user-specific features are later introduced.

Limits to keep in mind

  • Portfolio requests accept at most 40 holdings.
  • At most 16 NAV downloads run at the same time in one backend process.
  • Peer ranking uses at most 18 peers; recommendation scanning considers up to 120 candidates.
  • Chat messages and context have field, message-count, and total-size limits.
  • Tavily and chat counters live in memory, are not per-user, and are not shared across service instances. Fund chat and portfolio chat each keep a separate counter, even though they use the same configured cap value.
  • There is no database, user login, persistent portfolio storage, or background job queue in this backend.

The Tavily counter is checked before the network request and increased after a successful response. It is an in-process safety valve, not a billing-grade global quota: a restart resets it, multiple workers each have their own counter, and simultaneous requests near the limit can race. Chat caps use separate locked in-process counters; failed provider calls still consume a chat slot.

Deployment implication:

A short-lived serverless setup can restart between requests, and multiple replicas do not share these process-local values. If a deployment needs a single global quota or shared cache, it needs additional shared storage or coordination.

Dependency

A library the application imports to do a job, such as FastAPI for HTTP routes, httpx for network requests, or Pandas for dated numerical data.

Why declare dependencies?

Mini glossary

API

An agreed menu of addresses and actions one program offers another.

ASGI

The standard interface that connects Uvicorn to an asynchronous Python web application.

Await

Pause this async task until an operation is ready, allowing other tasks to make progress meanwhile.

Cache

A reusable saved copy that avoids fetching or recalculating the same thing immediately.

CORS

Browser rules about which website origin may read a cross-origin API response—not authentication.

Dataclass

A Python helper for defining a simple record with named fields.

Deterministic

Same inputs and settings follow the same code rules to produce the same calculation.

Endpoint / route

A method and address connected to a handler, such as GET /api/search.

Event loop

The scheduler that lets Python async tasks take turns, especially while other tasks wait for network I/O.

HTTP

The request-and-response protocol used to communicate with a web service.

JSON

Text representation of named values, lists, and nested data.

LLM

Large Language Model: software that generates or transforms text based on supplied context.

Middleware

Helper code that wraps request/response handling, such as CORS header handling.

Node

One specialist function in the LangGraph workflow.

Percentile

A relative position in a selected comparison group, not a chance of future success.

Process

One running copy of the backend program, with its own memory.

Semaphore

A counter acting like a traffic light: only a limited number of tasks pass at once.

SSE

Server-Sent Events: named text messages sent from server to caller over an open HTTP response.

TTL

Time to live: how long a saved copy can be treated as fresh.

Uvicorn

The web-server program that listens for network requests and connects to the ASGI app.
