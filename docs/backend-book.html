01

The backend map

Before opening individual files, learn the path a typical fund-review request follows.

Think of the backend as a small workshop. The API is the counter where a request arrives. Data modules fetch and prepare the raw material. Analysis modules do the arithmetic. The agent layer coordinates the work. The route packages the finished result for the caller.

api/

The front counter

Matches URLs, checks or receives request data, calls the right function, and returns JSON or a stream.

agent/

The coordinator

Runs a defined sequence of specialist functions. The sequence is written in Python rather than invented by an AI.

analysis/ + data/

The workshop

Data code finds and cleans information; analysis code turns that information into metrics and summaries.

First important boundary:

“Agent” describes the coordination layer. It does not mean an LLM makes the standard health score or verdict. Those are calculated by ordinary Python rules.

02

App startup and FastAPI

The backend begins as a Python object, then a web server makes it reachable over HTTP.

Two programs working together

Uvicorn

The listener

Uvicorn listens for network requests and passes them to the Python web application.

FastAPI

The request handler

FastAPI matches a request to a route, validates declared inputs, runs the handler, and builds the HTTP response.

ASGI is the agreed interface between them. Imagine a plug and socket: Uvicorn and FastAPI can connect because both follow the same standard.

backend/app/main.py · application creationOpen source file ↗
def create_app() -> FastAPI:
    settings = get_settings()
    app = FastAPI(
        title=settings.app_name,
        version="0.1.0",
        lifespan=lifespan,
    )
    app.add_middleware(
        CORSMiddleware,
        allow_origins=settings.cors_origins,
        allow_credentials=True,
        allow_methods=["*"],
        allow_headers=["*"],
    )
    app.include_router(router, prefix="/api")
    return app

app = create_app()
1 · SettingsRead environment values and prepare the cache directory before routes begin handling traffic.
2 · App objectFastAPI(...) creates the application object that Uvicorn will serve.
3 · MiddlewareCORS rules add browser-readable permission headers to responses. The browser checks those headers; they are not login protection.
4 · RouterAdding the router with prefix="/api" gives the handlers their public paths, such as /api/search.

What CORS actually does

A browser calls an address from a web page. If the page and API have different origins (protocol, host, or port), the browser asks whether the page is allowed to read the API response. Truthfolio’s CORS middleware configures the response that answers that browser rule.

It helps with

Allowing a known browser-based website—such as the local site at port 3000—to read responses from the API at port 8077.

It does not do

Authenticate a user, require an API key, or block command-line tools and other servers from calling the API.

Cookie note:

The app enables credentials in CORS, which permits browsers to include credential information when otherwise configured to do so. This backend does not thereby gain accounts or a login system.

Startup: warm one reference book

The FastAPI lifespan function runs startup work before the app serves requests. Truthfolio asks AMFI for its scheme directory early so the first search is usually faster. If that early attempt fails, the app still starts and a later request can try loading it again. NAV histories are not all downloaded at startup.

backend/app/main.py · startup lifecycleOpen source file ↗
@asynccontextmanager
async def lifespan(app: FastAPI):
    try:
        await amfi.get_master()
    except Exception:
        pass  # will retry lazily on first request
    yield

The startup load is best-effort. The handler’s broad catch applies to startup warming, not to every route. The service can report health even if a later fund request cannot reach AMFI.

03

Requests, routes, and validation

A request has an address, an action, and sometimes data. The route is the backend function assigned to that combination.

Read and send actions

GET

Ask for information

Examples: GET /api/search?q=parag, or GET /api/health.

POST

Send information or start work

Examples: POST /api/review with a scheme code, or POST /api/portfolio with holdings.

Validation as a form checker

A request model is a Python description of allowed fields and values. Pydantic reads it and rejects invalid data before the route starts the main work.

Validation is not the same as confirming that a scheme exists. A scheme code can be correctly formatted and still be unknown to AMFI; the route performs that lookup after validation.

Follow one real route

This small route accepts a fund code, looks up the official scheme, asks the review function to do the analysis, and shapes the final response.

backend/app/api/routes.py · review entry path (excerpt)Open source file ↗
async def _run_review(scheme_code: str, units=None, invested_amount=None):
    master = await amfi.get_master()
    scheme = master.get(scheme_code)
    if scheme is None:
        raise HTTPException(404, f"Scheme {scheme_code} not found in AMFI master.")
    try:
        state = await review_fund(
            scheme_code=scheme.code, scheme_name=scheme.name,
            category=scheme.category, base_name=scheme.base_name, amc=scheme.amc,
            units=units, invested_amount=invested_amount,
        )
    except ValueError as exc:
        raise HTTPException(422, str(exc))
    return ReviewResponse(**assemble_review(
        scheme_code=scheme.code, scheme_name=scheme.name,
        category=scheme.category, state=state,
    ))
1
Find the fund directory.

amfi.get_master() returns the prepared catalog.

2
Resolve the submitted code.

If it is absent, return HTTP 404; do not guess from a free-text name.

3
Run the review.

The official name, category, and fund house are passed to the coordinator.

4
Build a stable response.

assemble_review() shapes internal state; ReviewResponse describes the output.

Why a response builder?

Several paths can produce a fund review: a direct request, a streaming request, or a portfolio holding. A shared assembler helps them return a consistent review shape.

04

Finding the fund and loading NAV

AMFI answers “which official scheme is this?” mfapi.in answers “what has its published NAV history been?”

AMFI

The official directory

Its feed lists scheme codes, scheme names, fund houses, categories, plan/option details, and ISIN identifiers.

mfapi.in

The historical values

Its per-scheme response contains NAV observations with dates. The backend turns them into ordered points.

Why store scheme identity as a record?

The Scheme dataclass groups the facts that belong together: official code, display name, base fund name, AMC, category, plan, option, and optional ISINs. A SchemeMaster keeps lookup indexes by code and ISIN, plus a search corpus for name matching.

Fuzzy search is tolerant of reordered or partial words, but the code also checks that distinctive words from the query actually appear. This reduces accidental matches on made-up names. Duplicate plan/option versions collapse into one fund result, preferring Direct-Growth where available.

Search is not the same as trusting user text

Query text“flexi parag”
Find candidatesCompare with AMFI name corpus
Apply precision gateCheck meaningful words matched
Collapse variantsOne result per base fund
Return official codeDownstream work uses that identity

A NAV point and a NAV series

NavPoint is one dated observation. NavSeries contains a scheme’s metadata and points sorted oldest to newest, and exposes useful values such as the start date, end date, and latest NAV.

Make outside calls asynchronous and bounded

The client uses httpx.AsyncClient to perform an asynchronous HTTP request and Tenacity to retry failures up to three attempts. A shared semaphore allows at most 16 NAV downloads at once in this running backend copy.

Why cap simultaneous downloads?

A portfolio can trigger many holding reviews, and each review can compare peer funds. The semaphore is a traffic light that prevents an uncontrolled burst of requests to the NAV service.

05

Cache and outside services

A cache is a temporary saved copy, so the backend can reuse fresh public data rather than download it again.

Three possible places the fund directory can come from

1 · MemoryFastest; current running copy
2 · JSON cacheSaved on the local filesystem
3 · AMFIDownload and parse if no fresh copy
4 · IndexBuild code, ISIN, search indexes
5 · ReuseMemory copy until restart

For NAV history, the module checks the JSON cache. A fresh entry is parsed; a missing or old entry triggers a request to mfapi.in. The cache TTL defaults to 12 hours for NAV. The AMFI directory defaults to 24 hours on disk.

backend/app/data/cache.py · TTL decisionOpen source file ↗
def read(key: str, ttl_seconds: float) -> Any | None:
    path = _path_for(key)
    if not path.exists():
        return None
    try:
        payload = json.loads(path.read_text())
    except (json.JSONDecodeError, OSError):
        return None
    if time.time() - payload.get("_ts", 0) > ttl_seconds:
        return None
    return payload.get("data")
Code checkPlain meaningNext action
File missingNo copy is available.Caller fetches source data.
JSON cannot be readCopy is invalid or unreadable.Treat as a cache miss.
Age exceeds TTLCopy is too old for this feature.Fetch a newer copy.
Fresh timestampCopy is within its allowed age.Reuse stored data.
What “best effort” means:

Writing a cache copy is not allowed to break the actual request. If saving fails due to a file-system problem, the current request can still return the fetched data.

Cache is not database storage

  • The cache contains reusable public data and selected computed results.
  • It is local to each backend copy; multiple instances do not share it.
  • It does not save user portfolios or act as an account record.
  • Deleting it means data may need to be downloaded or calculated again.

Outside services by feature

AMFI

Scheme directory and official scheme codes.

mfapi.in

Historical NAV series for a scheme code.

Tavily

Search results for explicitly requested research or Market Pulse.

Anthropic

Optional language-model provider.

Groq

Alternative optional language-model provider.

No provider required

Ordinary fund metrics, peer ranking, and verdict calculations.

06

Review workflow and LangGraph

The graph is an ordered checklist with a shared clipboard. It coordinates steps but does not decide the order with AI.

Why break one review into specialists?

Each specialist has one responsibility: gather measurements, compare peers, prepare evidence, synthesize the result, or write an explanation. Keeping these jobs separate makes the result easier to inspect, test, and stream as progress.

The plans are explicit data

fund_insightsMetrics → peers → evidence → verdict → insight cards/insights

What a “state” is

AgentState is a typed dictionary shared across steps. Think of it as a clipboard: the quant specialist writes metrics, the peer specialist adds ranks, and later specialists read those fields and add their own results.

Analysis values

metrics, qualitative, peers, evidence, score, verdict, and narrative.

Control and progress

task, remaining plan, next-node name, progress steps, and whether optional AI was used.

One subtle but important boundary

Deep review can add researched web claims to the evidence list. The current synthesise() function receives metrics and peer data, not the combined evidence list. Therefore those web claims can enrich the evidence/explanation output, but do not alter the numeric score, confidence, or standard verdict.

07

Metrics, evidence, and verdict

Published NAV points become returns and risk measurements; the rules turn available measurements into a score and a named outcome.

First clean and order the timeline

analysis/metrics.py creates a dated Pandas series, removes duplicate dates (keeping the last), and sorts in chronological order. NumPy and Pandas help organize and calculate values; they do not decide the product’s scoring policy.

daily return = today’s NAV ÷ previous NAV − 1
example: 105 ÷ 100 − 1 = 0.05 = 5%

Growth and consistency

Trailing 1-, 3-, and 5-year returns; since-inception CAGR; rolling 3- and 5-year outcomes over multiple start dates.

Risk and downside

Annualized volatility, Sharpe ratio, Sortino ratio, and maximum drawdown from a previous peak.

Returns need a comparison group

A return can be high or low depending on the wider market. Peer comparison selects same-category Direct-Growth schemes, excludes the subject from the candidate set, limits each AMC to two schemes, and analyzes at most 18 peers. The reported comparison includes the subject fund among the ranked values.

A percentile is an approximate position in that comparison set. For example, 0.80 means the value is at least as good as about 80% of the compared values, while respecting whether high or low is better for that metric.

How the composite score is built

Each available component receives a 0–100 sub-score. Each component also has a fixed importance share. If a component is unavailable due to insufficient history, the remaining used weights are effectively normalized by dividing by their sum.

ComponentWeightWhat it reflects
Long-term return0.225-year CAGR, or 3-year when 5-year is unavailable; 0–20% maps to 0–100, capped.
Risk-adjusted0.26Average available Sharpe and Sortino; 0 to 1.5 maps to 0–100, capped.
Peer standing0.30Average available percentiles for 3-year return, 5-year return, and Sharpe.
Consistency0.14Negative rolling periods; prefers five-year windows.
Drawdown0.08Worst peak-to-trough fall; less severe fall earns a higher score.

Evidence explains; rules decide

build_evidence() turns metric and peer facts into readable items. An item can include a claim, category, direction, importance weight, confidence, and source references. The ledger helps people inspect the reasons. The arithmetic score is produced by the explicit scoring functions.

Not regulated advice:

Thresholds and portfolio rules are product rules of thumb. They are not regulated ratings, promises, or personalized investment instructions.

08

SSE, explained in code

Server-Sent Events keep one HTTP response open so the server can send progress updates before the final result.

Normal response or progress stream?

Ordinary route

Wait, then get one answer

POST /api/review waits for the review and returns one JSON object.

SSE route

Get updates, then the answer

GET /api/review/stream sends named progress events, then a final result event.

event: step
data: {"message":"Compared against same-category peers"}

event: result
data: { ...final review... }

An event consists of an event name and a data line. A blank line ends the event. The stream flows from the server to the caller; the caller does not send new instructions through that same stream.

Frame builder: two lines plus a blank line

backend/app/api/routes.py · SSE frameOpen source file ↗
def _sse(event: str, data: dict) -> str:
    return f"event: {event}\ndata: {json.dumps(data, default=str)}\n\n"
Event lineevent: step or event: result lets the receiver distinguish message types.
Data lineThe Python dictionary is converted to JSON text for the stream.
Blank lineThe final \n\n tells the receiver this event is complete.

Streaming a fund review

backend/app/api/routes.py · event generator (excerpt)Open source file ↗
async for chunk in graph.astream(initial, stream_mode="values"):
    final_state = chunk
    steps = chunk.get("steps", [])
    for step in steps[last_steps:]:
        yield _sse("step", {"message": step})
    last_steps = len(steps)

result = assemble_review(..., state=final_state)
yield _sse("result", result)

return StreamingResponse(event_gen(), media_type="text/event-stream")

The graph emits updated state values as its nodes finish. The route remembers how many progress messages it already sent, then sends only the new ones. At the end, it builds the same review response as the ordinary path and emits it as result.

Streaming a portfolio

The portfolio stream emits start, then a holding event whenever an analysis finishes, and finally result. The completed-holding order can differ from the order submitted because tasks are collected as they finish.

EventWhat it meansWhen sent
startHow many holdings are being analyzed.At stream start.
stepA new review-progress message.As a fund-review node adds a step.
holdingOne portfolio holding succeeded or failed.When each holding task finishes.
resultFinal review or aggregate portfolio result.At successful completion.
errorA stream-level failure message.When an error is reported after streaming begins.
HTTP status vs stream error:

The HTTP response status is chosen when the stream starts. An error discovered after that point is commonly carried as an SSE error event instead of changing the already-started HTTP status.

09

Portfolio analysis

Each submitted holding receives the same fund-review treatment, then a separate calculation combines successful holdings.

What a holding needs

scheme_code + units held + average purchase NAV

PortfolioRequest allows between 1 and 40 holdings. A holding with a missing scheme, failed review, or missing latest NAV is not included in the successful aggregate.

One holding’s path

1
Find scheme identity.

Resolve the supplied official scheme code against the AMFI directory.

2
Calculate amount invested.

Multiply units by the average purchase NAV supplied by the caller.

3
Run the same fund-review graph.

Gather NAV metrics, compare peers, build evidence, score, and explain.

4
Add personal position figures.

Use the latest NAV from the computed report to calculate current value and gain.

Personal position equations

invested = units × average purchase NAV
current value = units × latest NAV
gain = current value − invested
return fraction = gain ÷ invested

The returned personal return is a fraction: 0.10 means 10%. It is total return from the supplied cost basis, not annualized. The request does not contain purchase dates or cash flows, so the backend cannot derive a time-weighted personal return.

Concurrency: many analyses, bounded downloads

backend/app/api/routes.py · parallel holding analyses (excerpt)Open source file ↗
inputs = [HoldingInput(h.scheme_code, h.units, h.avg_nav) for h in req.holdings]
results = await asyncio.gather(*(analyze_holding(h) for h in inputs))
valid = [result for result in results if result is not None]
if not valid:
    raise HTTPException(422, "None of the submitted funds could be analysed.")

asyncio.gather() starts the holding analyses without waiting for each one to finish before starting the next. Separately, the NAV semaphore limits how many network downloads happen simultaneously. So the backend can work on many holdings while still controlling the outside request rate.

Aggregate the successful holdings

  • Sum invested value, current value, gain/loss, and total return.
  • Calculate each holding’s share of current portfolio value.
  • Group current value by fund category.
  • Measure concentration using HHI: square each holding’s share and add the squares.
  • Calculate current-value-weighted portfolio health, then apply a concentration penalty.
  • Return a portfolio verdict, best/worst personal return, and action observations.
HHI = share₁² + share₂² + … + shareₙ²
Two equal holdings: 0.5² + 0.5² = 0.50
One holding: 1.0² = 1.00

The synchronous route returns the final portfolio object once. The streaming route reports each holding completion and then calls the same portfolio aggregation logic for the final result.

10

CAS statement import

A Consolidated Account Statement is uploaded, parsed for active holdings, and matched to the official scheme directory.

CAMS and KFintech maintain mutual-fund account records. The route accepts a PDF and optional password. The casparser library reads it. Because PDF parsing is blocking work, the backend sends it to a worker thread so the main asynchronous request loop can continue serving other requests.

Read a limited number of bytes

backend/app/api/routes.py · upload boundary (excerpt)Open source file ↗
data = await file.read(settings.cas_max_bytes + 1)
...
if len(data) > settings.cas_max_bytes:
    raise HTTPException(413, "File is too large...")

result = await asyncio.to_thread(cas_import.import_cas, data, password, master)

Reading at most the limit plus one byte makes it possible to detect an oversized upload without reading the whole file. The default maximum is 15,000,000 bytes. The parser returns active schemes with closing units above zero and tries to match them using AMFI code first, then ISIN.

Freshness policy

By default, statements older than 30 days get a warning. Statements older than 90 days are rejected.

Sensitive content

The route does not intentionally write or log the PDF/password or send them to search or AI. It clears its local references after parsing; this is not a guaranteed secure erase of Python memory.

Import prepares holdings; it does not itself run the portfolio analysis. The returned holdings are submitted to /portfolio or /portfolio/stream for review.

Optional AI and web research

AI is an optional writing and synthesis tool around calculated data; web research is explicit and gated separately.

Feature gates

Setting/propertyWhat must be configuredEnables
llm_enabledKey for selected providerNarrative, chats, AI insight cards
search_enabledTavily keySearch requests
research_enabledLLM key and Tavily keyClaim appraisal and research summaries

/capabilities reports whether these features appear configured. A capability response is for feature discovery; the route checks configuration again when a request is actually made.

AI writes around the result; it does not replace the result

Code computesMetrics, peer ranks, score, verdict
Prepare contextSend existing results to model
Model draftsNarrative text or insight cards
Backend checksKeep fixed verdict and caveats
Return resultUse template if optional AI fails

If there is no key, the standard review uses a deterministic narrative template. If the configured model call fails, the backend also uses a template. The arithmetic verdict remains unchanged.

Research is on-demand

GET /api/research is the explicit fund-research path. It asks Tavily for two kinds of search (fund facts and recent news/regulatory context), then screens and appraises results before asking an LLM to extract cited claims.

1
Search.

Fetch results for the requested topics, subject to the daily cap and cache.

2
Clean and appraise.

Drop unusable result rows and calculate a transparent source score using domain, date, and corroboration.

3
Build citations.

Deduplicate source URLs and assign stable first-use numbers.

4
Extract claims.

Ask the model for concise claims with citation numbers; reject claims without valid citations.

Credit boundary:

The ordinary fund review does not automatically spend Tavily credits. Research and Market Pulse are separate features. Search results that fail do not increment the successful uncached-request counter.

What data goes to outside AI?

Deterministic path

Ordinary NAV metrics, peer ranking, and the numeric verdict are computed in this backend. They do not need an LLM provider.

Optional path

When a feature calls an LLM or search service, the context needed for that feature is sent to that outside provider. Chat services do not store a server-side transcript.

Operations and system boundaries

How configuration, errors, limits, and process-local memory shape what operators should expect.

Where settings come from

Settings uses Pydantic Settings to read environment variables and a local .env file. Most settings use the HPR_ prefix. Provider selection and keys accept both common unprefixed names and prefixed alternatives.

Common outcomes

SituationTypical resultMeaning

What belongs to one running copy?

Memory

Loaded AMFI master, compiled graph, and usage counters remain in a process’s memory.

Local disk

JSON cache files live in that instance’s configured cache folder.

Not shared automatically

Multiple app instances have separate in-memory counters and may have separate filesystems.

Limits to keep in mind

  • Portfolio requests accept at most 40 holdings.
  • At most 16 NAV downloads run at the same time in one backend process.
  • Peer ranking uses at most 18 peers; recommendation scanning considers up to 120 candidates.
  • Chat messages and context have field, message-count, and total-size limits.
  • Tavily and chat counters live in memory, are not per-user, and are not shared across service instances.
  • There is no database, user login, persistent portfolio storage, or background job queue in this backend.
Deployment implication:

A short-lived serverless setup can restart between requests, and multiple replicas do not share these process-local values. If a deployment needs a single global quota or shared cache, it needs additional shared storage or coordination.

Mini glossary

ASGI

The standard interface connecting Uvicorn to an asynchronous Python web application.

Middleware

Helper code that runs around a request or response, such as CORS handling.

TTL

Time to live: how long a saved copy can be treated as fresh.

Semaphore

A counter acting like a traffic light: only a fixed number of tasks may pass at once.

Dataclass

A Python helper that creates a simple record-like class for related values.

Deterministic

Given the same inputs and settings, the code follows the same rules and produces the same calculation.
